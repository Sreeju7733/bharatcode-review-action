What is BharatCode PR Reviewer?

BharatCode PR Reviewer is an enterprise-grade TypeScript GitHub Action that acts as a tireless, automated senior staff engineer on every Pull Request. It evaluates changed code diffs, highlights anti-patterns, checks for security exploits, provides ready-to-commit code suggestions, and updates severity labels automatically.

🎯

Inline Review Comments

Maps findings directly to unified diff line numbers with GitHub-native one-click code replacement suggestions.

🏷️

Auto-Synced Labels

Automatically manages PR labels (bug, needs-review, nit) based on active findings.

🛡️

Local Regex Rules

Executes local regex checks before calling AI models, catching banned patterns and secrets at zero API cost.

🔄

Provider Failover

Cascades to OpenAI (gpt-4o-mini) or Anthropic (claude-3-5-haiku) if the primary API encounters 429 or 5xx.

Single Repository Quickstart

Deploy BharatCode on an individual repository in two quick steps.

1

Add Repository Secret

Go to your GitHub repository: Settings → Secrets and variables → Actions → New repository secret:

  • Name: BHARATCODE_API_KEY
  • Secret: Paste your API key from bharatcode.ai
2

Create Workflow File

Create .github/workflows/bharatcode-review.yml in your repository:

name: BharatCode PR Review

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write
  issues: write
  checks: write

jobs:
  review:
    name: Review PR Changes
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Run BharatCode Reviewer
        uses: BharatCode-ai/bharatcode-review-action@v1
        with:
          bharatcode-api-key: ${{ secrets.BHARATCODE_API_KEY }}
          github-token: ${{ secrets.GITHUB_TOKEN }}
          mode: "summary+inline"
          severity-threshold: "warning"
          fail-on-severity: "error"

Organization-Wide Bulk Rollout (All Repositories)

Deploying across 20, 50, or 200 repositories? You do not need to edit repositories individually. Follow our automated rollout playbook.

Step 1: Set Organization Secret

Configure BHARATCODE_API_KEY once at the organization level so every existing and future repository inherits it automatically: 

# Using the GitHub CLI:
gh secret set BHARATCODE_API_KEY --org "Your-Org-Name" --body "bc_your_api_key" --visibility all

Step 2: Run the Automated PR Rollout Script

We include an enterprise rollout script: scripts/rollout-action.sh. It iterates across all non-archived repositories in your organization, creates a clean branch, commits the review workflow, and opens an automated PR for repository maintainers to merge: 

export GH_TOKEN="ghp_your_github_admin_token"
export BHARATCODE_API_KEY="bc_your_api_key"

# Run bulk rollout across all org repos
./scripts/rollout-action.sh
Enterprise Safety Guarantees:
  • Pull Requests Only: The script never pushes directly to default branches.
  • Idempotent: Skips repositories where the action is already configured.
  • Archived Filter: Automatically skips archived, template, and disabled repositories.

Step 3: Centralized Governance via Reusable Workflow

For centralized policy enforcement, repositories can reference the reusable workflow: 

jobs:
  review:
    uses: BharatCode-ai/bharatcode-review-action/.github/workflows/reusable-review.yml@v1
    secrets:
      BHARATCODE_API_KEY: ${{ secrets.BHARATCODE_API_KEY }}

Configuration Reference

Action Inputs

Input Default Description
bharatcode-api-key Required BharatCode API Key (pass via secrets.BHARATCODE_API_KEY).
github-token Required GitHub Token with pull-requests: write permissions.
model glm-5.3-flash Evaluation model: glm-5.3-flash (Free 10M/day) or deepseek-v4.1-flash (Pro).
mode summary+inline Review format: summary, inline, summary+inline, or gate.
severity-threshold warning Minimum severity level to comment on: info, warning, or error.
fail-on-severity none Fails CI check run if findings match threshold: none, warning, or error.
post-labels true Automatically add/remove severity labels on the PR.
cache-enabled true Avoid duplicate LLM costs on re-runs by caching commit SHA hashes.
max-usd-budget 0 Hard spend limit in USD per PR run (0 = unlimited).

Repository Config File (.bharatcode-review.yml)

Place this file in your repository root to configure local zero-cost regex rules and exclusions:

# Model override
model: glm-5.3-flash

# Excluded patterns
ignore-globs:
  - "docs/**"
  - "**/*.lock"
  - "**/generated/**"

# Pre-flight zero-cost regex rules
rules:
  - name: no-console-log
    pattern: 'console\.(log|debug)'
    severity: warning
    category: style
    message: "Remove console debug statements before production merge."

  - name: avoid-hardcoded-secrets
    pattern: 'AKIA[0-9A-Z]{16}'
    severity: error
    category: security
    message: "Potential hardcoded AWS Access Key detected!"

Multi-Provider Failover

For critical pull request workflows where review checks are required before merging, configure secondary fallback providers. If BharatCode encounters rate limits or temporary network downtime, the action automatically falls back: 

- uses: BharatCode-ai/bharatcode-review-action@v1
  with:
    bharatcode-api-key: ${{ secrets.BHARATCODE_API_KEY }}
    github-token: ${{ secrets.GITHUB_TOKEN }}
    fallback-providers: "openai,anthropic"
    openai-api-key: ${{ secrets.OPENAI_API_KEY }}
    anthropic-api-key: ${{ secrets.ANTHROPIC_API_KEY }}
